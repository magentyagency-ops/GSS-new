## Cause racine (≠ hypothèse initiale)
`cloneSpread` **clone bien** l'en-tête (`newHeading = headingParas.map(cloneNode(true))`), donc le
bandeau (logo + bande + textbox) est copié. **MAIS** juste après, `cloneSpread` appelle
**`stripStandaloneBgImages(newHeading)`** qui supprime tout run `behindDoc="1"` + `blip` **sans**
`txbxContent`.

Analyse des images réellement supprimées par `stripStandaloneBgImages` (sur le template) :
**uniquement des petites images ≤ 3 Ko**, dont **`image5.png` (logo GSS) ×93**, `image32.png` ×11,
`image2.png`, pictos/filets ≤1 Ko. **Aucune grande image de fond pleine page** dans la liste.

→ **`stripStandaloneBgImages` retire le LOGO du bandeau** (image5) des pages clonées (run
`behindDoc` sans textbox), alors qu'il était censé retirer les **fonds décoratifs pleine page**.
Le `txbxContent` (breadcrumb) survit (il a un textbox) → sur les clones : **texte de section seul,
sans logo ni bande** = bandeau « cassé » constaté par Stan.

`memoire_generator.ts` :
- `cloneSpread` (clone heading) → appelle `stripStandaloneBgImages(newHeading)` (l. ~439).
- `stripStandaloneBgImages` (l. ~378) : `if (isFullPageBg && hasBlip && !hasTitle) remove` → retire le logo image5.
