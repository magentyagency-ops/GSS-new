## 1. Blocs décoratifs (cf. [V1.2_DECORATIVE_INVENTORY.md](V1.2_DECORATIVE_INVENTORY.md))

**Racine** : le maître AO RNE.docx contient, sur les pages de section, des blocs « photo
d'agent + légende » (« NOS AGENTS CYNOPHILES » + chien, « NOS AGENTS INCENDIE SSIAP » +
extincteurs, etc.). Ils sont **dupliqués** par `cloneSpread` lors de la génération. V1.1
n'avait retiré que `image8.jpeg` (1 bloc) ; le problème est **catégoriel** (7 blocs).

**Critère de suppression robuste (au niveau du run `<w:r>`)** :
- le run embarque une **photo > 40 Ko** (hors logos `image5/image2/image32`) ;
- **ET** il contient **exactement 1 légende distincte courte** (`txbxContent`, ≤ 6 mots).

→ Capture exactement les **7 blocs décoratifs**, et **exclut** :
- les logos (petits, < 40 Ko) ;
- les fonds `behindDoc` (couverture, séparateurs) ;
- les **diagrammes fonctionnels** (`image109/132/180`) qui portent **plusieurs** légendes.

## 2. Bandeau header dégradé

**Symptôme (Stan)** : sur certaines pages, le bandeau « I. PRESENTATION / 1. NOTRE CATALOGUE… »
n'a plus que du texte olive peu visible, sans fond gris foncé / logo cohérent.

**Cause racine identifiée** : dans `cloneSpread`, après clonage de l'en-tête, le code appelle
`forceTextColor(newHeading, DUP_TEXT_COLOR /* #1A1A1A */)` (memoire_generator.ts l.311) qui
force **tous** les runs textuels en sombre — **y compris** le texte du bandeau (`txbxContent`).
Sur le bandeau à fond foncé, un texte sombre devient **invisible/olive très peu lisible**.
(C'était l'objet du fix V1.1, **non présent** dans cette base car PR #5 n'est pas mergée.)

**Correctif** : `forceTextColor` doit **épargner les `txbxContent`** (bandeaux de titre), pour
préserver leur couleur claire d'origine → texte clair sur bandeau foncé, lisible sur chaque
page. Le corps (hors `txbxContent`) reste forcé en sombre (lisible sur le fond gris).

> Le logo du bandeau est `image5.png` (188 réf., conservé) ; il n'est jamais retiré par la
> suppression décorative (taille < 40 Ko + exclu explicitement).
