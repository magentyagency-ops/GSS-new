## ⚠️ Limite technique bloquante identifiée (honnête)

Le bandeau inline (zone B) est une **zone de texte flottante** (`wps`/`txbxContent`). **LibreOffice
ne rend ni le `solidFill` de forme ni le `w:shd` de paragraphe à l'intérieur de ces zones de texte
flottantes** : le XML est correct (362 bandes `#494545` + texte clair) mais le rendu LibreOffice
(utilisé pour les captures) **n'affiche pas** la bande foncée. Trois approches testées
(préserver la bande flottante / `solidFill` de forme / `w:shd` de paragraphe) → aucune visible
sous LibreOffice.

- **MS Word** rend généralement le `w:shd` dans les zones de texte → le correctif V1.4
  **pourrait** afficher le bandeau dans Word. **Non vérifiable** ici (pas de Word).
- Le **seul** bandeau qui s'affiche de façon fiable sous LibreOffice est l'**en-tête Word V1.3**
  (zone A) : bande foncée + logo GSS + « MÉMOIRE TECHNIQUE — GSS » sur **chaque** page (visible
  page 5). Mais il est générique (pas de titre par section) et la mission interdit d'y toucher.

## Recommandation
Le bandeau **par section** fiable (logo + numéro + titre + sous-titre, rendu dans LibreOffice ET
Word) passe par des **en-têtes Word multiples** (un `header*.xml` par section, `headerReference`
ciblé) — extension de la zone A (V1.3). C'est la voie robuste pour V1.5. Décision à valider par Stan
(la mission verrouillait la zone A).
